1 · The failure we are fixing

iOS suspends the Vlervtifacts app when it leaves the foreground and closes its sockets. A push from the MCP server then fails in one of two ways, both observed in a live session on 2026-09-02:

localhost (50baf24c5c) is not reachable: peer offline — could not reach it (timed out).
the session is closed

The second message is the important one. McpCore::session returns a cached session without dialing while is_closed() reads false (crates/vlerv-mcp/src/core.rs:650-657), and is_closed() is a cached AtomicBool, not a probe (crates/vlerv-remote/src/scope.rs:1123). After an iOS suspension the flag is still false, so the failure arrives from request, not from the dial.

Consequence for the design. A queue that classifies only dial failures never fires in the exact case the user hit. The push failure must be typed too.

There is no UIBackgroundModes key in src-tauri/Info.ios.plist and no APNs code in the repository. Nothing can wake the app. The chosen fix therefore does not try to: it accepts the send, holds it, and delivers it the next time the device is reachable.

2 · The decision, and what does not change

A sender-side durable outbox in vlerv-mcp, drained by the process that holds the blob-store lock. No central server, no relay with storage, and no change to the product promise that nothing is uploaded to a server.

AreaDecision
Wire protocolUntouched. No new Req, Res or Event variant, no HelloAck field, no new ALPN, PROTO_VERSION stays 1. The queue replays the existing Req::PushArtifact (wire tag 9).
Who owns the queueThe process holding remote/blobs.lock. The StoreLock already permits one process per state directory, so it is the outbox lock too. No second lock.
What is storedThe bytes, staged into the blob store at enqueue and pinned by a named tag. Not a path re-read later.
Delivery guaranteeAt least once. A duplicate lands visibly as report-2.html through the existing Beam collision rule.
Tool surfaceNo new MCP tool. send_to_device returns a tagged Delivery enum: Delivered or Queued.

Why no new protocol verb

An appended Req variant sent to an older peer is not ignored. decode_frame returns Err (proto.rs:195-197), ScopeServer::serve propagates it (scope.rs:933-938), and the connection closes. The client then reports the session is closed — the exact string of the bug being fixed, and indistinguishable from a sleeping phone. Appending a field to HelloAck breaks the other direction: postcard ignores trailing bytes, so a new reader of an old payload fails with DeserializeUnexpectedEnd.

Standing rule. Capability discovery is the ALPN. If a wire verb is ever required, register it on its own ALPN beside SCOPE_ALPN and PAIR_ALPN, so an older peer refuses the dial locally instead of having an established session torn down.

3 · How a delayed delivery works

What decides "queue" instead of "fail"

Two new error enums in scope.rs, each with a Display that yields the inner string verbatim so no user-visible sentence changes byte for byte:

pub enum ConnectError { Unreachable(String), Refused(String) }
pub enum PushFailure  { Local(String), Transport(String), Denied(String) }
CauseVariantOutcome
dial failed, or the peer did not answer the handshakeUnreachableenqueue
stream refused, version mismatch, Res::Denied, unexpected frameRefusedhard error
request returned the session is closedTransportre-dial once, then classify the re-dial
path gate refused, malformed peer id, staging failedLocalhard error
host answered Res::DeniedDeniedhard error

Never queue a caller error. A bad path, an unknown device, a missing control grant and a claimed store all fail loudly with today's wording and stage nothing. A caller error that silently becomes a pending delivery is the bug class this repository hunts.

The grant pre-check

peers::Peer gains last_ack_scope: Option<String>, written on every successful handshake. If it says the device granted less than control, the send is refused and nothing is staged. Without this, a device that never granted control accumulates private full copies of user files for the whole retention window. The field is a hint, never an authority: the receiver's own Scope::allows filter still decides whether bytes may land.

4 · On-disk model and blob lifetime

One file per record at <base>/remote/outbox/<id>.json, mode 0600, beside identity.key in the same privacy class. A whole-list document is rejected because completing a delivery must be an atomic remove_file that cannot lose an unrelated record, and because a corrupt document must poison one delivery rather than the whole spool.

pub struct Record {
    pub id: String,          // "{unix_millis:013}-{seq:04}"
    pub peer: String,        // 64-hex EndpointId, the peers.json key
    pub device: String,      // display only, as it stood at enqueue
    pub source: PathBuf,     // the canonical path the gate resolved
    pub name: String,
    pub size: u64,
    pub hash: String,        // BLAKE3 hex of the STAGED bytes
    pub tag: String,         // "outbox/<id>" — the pin
    pub enqueued_at: u64,
    pub expires_at: u64,
    pub attempts: u32,
    pub last_attempt_at: u64,
    pub last_error: Option<String>,
}

The record holds no BlobTicket and no grant. Both are minted per attempt: a stored ticket names addresses this process no longer has, and grants are in-memory with a one-hour lifetime.

The id carries no content suffix, and it cannot: the tag name has to exist before the single staging await that both copies the bytes and pins them, while the content address only exists once that await has returned. So the counter is the whole of what makes an id unique, and it is seeded past every sequence number the directory already holds rather than restarted at 0 — a machine whose clock reports a time before 1970 stamps every id 0000000000000, and a restart would then mint an id an earlier run already used.

Caps

ConstantValueBehaviour at the limit
MAX_RECORDS64refuse the send, naming the cap and the device
MAX_SPOOL_BYTES1 GiBrefuse the send
RECORD_TTL_SECS7 daysexpire, unpin, report in server_status
DRAIN_TICK60 stimer branch, skipped while the spool is empty
MAX_PER_PASS8pushes per peer per pass, walking the records in id order

A full spool refuses the send. It never drops the oldest record: the received log drops its oldest because that is a log line, while the oldest queue record is the user's file.

Why the bytes are captured at enqueue

Claude Code writes a file and keeps editing it. Re-reading the source at drain time would deliver bytes the user never accepted, or fail outright on a deleted file. add_path is ImportMode::Copy, so the store's copy is independent of the source. Staging is one await — add_path(path).with_named_tag("outbox/<id>") — rather than add, then set a tag, then delete the automatic one, whose crash window leaks an auto-* tag that an outbox/ prefix sweep can never collect.

Corruption policy: three causes, one list

Every stem the spool could not put on the record list lands on the same unaccounted vector, and every one of them stays in the tag keep-set — bytes this build cannot account for are the last thing it should delete. One list rather than three, because all three consumers want exactly that union: the keep-set, the id counter and the status surface. Split, a fourth cause would reach only the lists somebody remembered to widen, and a stem missing from the keep-set unpins a pending send with no error anywhere. What the cause decides is what happens to the file:

  • A record this build cannot parse is renamed to <id>.json.broken.<unix> and never replayed. No later boot changes that answer.
  • A record written by a newer schema version is left byte for byte alone, for the build that can read it.
  • A record whose bytes would not read at all — EACCES after a permissions repair, a changed owner after a restore, EIO on a bad sector — is left alone too. The record behind it may be perfectly valid, and quarantining it would rename a promised delivery and abandon it over a condition that passes on its own.

The list is surfaced by NAME on server_status.queue_unreadable, never as a count: each entry is a delivery that is quietly not happening. A quarantined stem stays on it at every later boot, not only the boot that moved the file aside, because the alternative is a delivery reported once and then silently forgotten.

The outbox DIRECTORY failing to read is a wider failure than any of the three, and it is handled apart: enqueue refuses, the tag sweep does not run, and queue_blocked_reason carries the cause.

The data-loss path these guards close. Without them, one unreadable spool makes the live set empty, the sweep unpins every staged copy, and the pending files are gone with no error.

Grants must not unpin queued bytes

Grant.tag becomes Option<Tag> and Grants::grant_pinned inserts with None, meaning "another owner pins these bytes". This is required, not defensive: stage_for_peer calls take_expired on every invocation (scope.rs:807) and deletes the returned tags, so without it the one-hour grant lifetime would unpin a queued file an hour after enqueue and the drain would push a hash with no bytes behind it. Expired grants are still removed from the map and still refused by admit — only the tag collection is conditional.

The hour is kept PER PEER, in a map from EndpointId to expiry, because unrelated callers share one hash. A queued send re-grants the same bytes to its own device on every attempt that reaches a push, and one grant-wide clock would let that repetition renew a browse capability some other peer earned once. So take_expired drops the lapsed peers first and takes the entry — and its tag — only when the LAST peer lapses: dropping the whole entry on the first lapse would free bytes a peer still inside its hour is allowed to fetch. revoke_peer splits the same way for unpairing.

Deleting a tag frees disk. Step 8 shipped, so this is no longer a caveat. endpoint::boot opens the store through FsStore::load_with_opts with a GcConfig on a 60-second interval, and the collector roots on persistent tags plus an import's temp tags. A pin released by a delivered record, a revoked link or an expired grant is reclaimed at the next collection. server_status.retained_bytes still reports what the queue is holding, and it is now a floor by about a minute rather than for the life of the install.

5 · Drain triggers and backoff

TriggerPrecision
T1HostSignal::PeerConnected, emitted in ScopeServer::accept right after the HelloAck is queuedExact. The phone dialing in is the receiver-initiated leg, and it needs no wire verb.
T2Boot: one pass after reconciliationDelivers work left by a dead process.
T3Timer with a per-peer floor: 60 s, 2 min, 5 min, 10 min, then 10 minFallback. Backoff lives in memory, so a restart retries at once.
T4A successful inline send to a peer notifies that peer's wakerOpportunistic.

The 60-second floor is a privacy decision as much as a cost one. Every retry is an n0 discovery lookup and a possible relay traversal, so each avoided dial is one less third-party observation of who talks to whom.

Records are grouped by peer before dialing. A dial to a suspended peer costs the full 30-second timeout, so five records for one sleeping phone must cost one dial, not five.

The peers then run TOGETHER, not one after another: the pass collects every due peer and drives them under one join_all on the supervisor's own task, the way list_devices { probe: true } probes. Serial peers would make one sleeping phone hold up a delivery to a phone that is awake, and a fleet with three sleepers would pay three dial timeouts before the fourth device is tried. It is still one task, so two passes cannot overlap; the per-peer in-flight guard is what stops anything else pushing a record twice.

6 · Work plan, eight steps

Each step is independently shippable and ordered. Steps 1 to 6 are the queue. Step 7 makes the phone reachable at all. Step 8 reclaims disk.

Step 1 — Typed session and push failures, with no behaviour change core scope.rs · core.rs · src-tauri/src/remote.rs

Add ConnectError and PushFailure. Change ClientSession::connect and push_artifact_via to return them. Every call site keeps its exact wording through Display. Nothing string-sniffs: matching a PEER_OFFLINE prefix is literally unreachable, because McpCore::session wraps the dial error as "{label} is not reachable: {e}. …" and puts the marker in the middle.

This step also replaces the tempting session.is_closed() state test, which races: writer_closed is stored only after send.finish() and reader_closed only after the read loop breaks, so the error can be observed while both flags still read false.

Step 2 — Pinned grants and the staged-push trio core scope.rs

Grant.tag becomes Option<Tag>; take_expired and revoke_peer keep their predicates and only collect Some tags. Add Grants::grant_pinned. Add push_staged, push_staged_at and push_staged_via beside the existing push trio: they take a hash instead of a path, parse it through beam::parse_hash, re-grant per attempt, and mint a fresh BlobTicket on the current endpoint address. The length guard lives in parse_hash rather than at this call site, and four call sites share it. That is the whole reason the helper exists: Hash::from_str reads any string that is not 64 characters as base32 and can PANIC on malformed input, and every one of those callers hands it a string this process did not mint — an offer id off IPC, a content address off the wire, one read back out of a hand-editable record file. The no-argument form carries the bounded 10-second endpoint.online() wait; omitting it would mint a ticket with no relay address, which delivers on the same LAN and fails everywhere else.

Step 3 — The outbox module and its blob helpers core paths.rs · outbox.rs (new) · beam.rs · lib.rs

Dirs::outbox() beside received(), plus the line in every_path_derives_from_the_one_base. The new module carries Record, Outbox, the five constants and the load / enqueue / complete / expire surface. Persistence copies the shape of peers.rs:351-377: disk before memory, tmp plus rename, 0600, the mutex never held across an await. The tmp-plus-rename is not copied twice, though — it is lifted into one writer, paths::write_private_atomic, and PeerStore::save_list now calls the same function. A second private writer is how one of these capability documents silently loses its 0600, and the staging name is load-bearing for the spool: it appends .tmp rather than replacing the extension, because the record reader keys off the last extension and would read a <id>.json leftover back as a record. The id is claimed with create_new so a backwards clock jump fails loudly instead of overwriting an accepted send. No iroh type appears in any signature, per the lib.rs invariant.

Step 4 — Accept and persist: enqueue, the tagged Delivery, the status surface core core.rs · server.rs · peers.rs

Delivery becomes a #[serde(tag = "status")] enum with Delivered and Queued. A tagged enum still serializes to a JSON object, which structuredContent requires, and the type stops the render code compiling until it decides which case it prints. Add outbox: Arc<Outbox> to McpCore, loaded in new() so new() still binds nothing. Add last_ack_scope to Peer; PEERS_SCHEMA stays 1 because Peer does not deny unknown fields. server_status grows the queue depth, the retained bytes, the per-record state and the reason a drain is blocked.

Step 5 — The drain: reconciliation, supervisor, per-peer pass core core.rs · beam.rs · tests/tool_handlers.rs

One tokio::spawn inside the boot() OnceCell initializer, after endpoint::boot returns Ok. Spawning there and nowhere else preserves the lazy-boot contract the tests already assert: a registered but unused server still binds nothing. Boot order is reload, then drop records whose bytes are gone, then the guarded orphan-tag sweep, then the supervisor, which runs one pass immediately. The supervisor is a single select! over the wake channel and the tick, so two passes cannot overlap by construction.

Per pass: expire, group by peer, then drive every due peer at once under one join_all on that same supervisor task. Per peer: unpaired means drop and unpin; unreachable records the attempt and ends the pass; a scope below control writes today's actionable instruction as last_error. Per record: a lexical roots check (not a fresh canonicalize, so a snapshot stays deliverable after the source is deleted), a bytes-present check, then the push. On success, delete the record file first and unpin second, so a crash between the two leaks a tag the next boot sweep collects rather than leaving a record whose bytes are gone.

MAX_PER_PASS is COUNTED over the pushes, never sliced off the front of the list. Only a record that reaches push_staged spends the session; a held or byte-less one costs a string compare. Spending the budget on skipped records starves the deliverable records behind them — the state directory is shared by every Claude Code session while VLERV_MCP_ROOTS is per project, so eight records another project queued for the same phone sit at the head of that peer's list as a matter of course, and the ninth would wait out the whole seven-day TTL behind them.

Step 6 — The wake signal core host.rs · scope.rs · core.rs · src-tauri/src/remote.rs

Append PeerConnected { peer, device, scope } to HostSignal and emit it right after the HelloAck is queued, so the signal means "this peer holds a working session", not "this peer knocked". PeerDisconnected is deliberately not added: the drain learns the truth from its own dial, and every variant costs both consumers an arm. The app's sink logs and returns; the frozen vlerv://* webview event namespace gains no name.

Step 7 — The app side: make the phone reachable at all core app.rs · remote.rs · state/remote.tsx · Settings.tsx

Without this step the fix is inert on a default install. preferences.remote_listen defaults to false and listen_at_launch returns before it spawns anything when the flag is off, so the phone boots no endpoint and the sender's dial can never connect.

What shipped is a one-way MIGRATION rather than a platform test in the predicate. The first launch of a receiver build that already trusts somebody writes remote_listen: true and a remote_listen_adopted marker, and listens_at_launch goes on reading the preference on both platforms. A platform test there would have made an off switch a lie: state.json would say the app listens to nobody while it binds a socket at every launch. The marker is what makes it one-way — a user who turns the switch back off stays off, because every later launch reads the marker and leaves the preference alone — and an unpaired install is left untouched, so the lazy-boot promise still holds for a fresh one.

The Settings toggle therefore stays VISIBLE on iOS. The migration writes the value the backend reads, and hiding the row would leave a stored preference the user can neither see nor undo.

Step 8 — Real byte reclamation core endpoint.rs · beam.rs · core.rs · README-MCP.md · STATUS.md

Both halves landed with the rest, so this is no longer deferred. endpoint::boot opens the store through FsStore::load_with_opts with a GcConfig on GC_INTERVAL, 60 seconds — the same cadence the queue drains at — and sweeps orphan auto-* tags at boot through beam::sweep_auto_tags. The sweep is safe by construction because StoreLock means one process owns the store: an auto-… tag present at boot was written by a process that is gone, and both registries the request gate consults live in memory only, so no offer and no grant can name its hash again. outbox/… tags are deliberately left out of that sweep — they name a promise that DOES survive a restart, and the spool sweeps its own prefix behind its own guard. The collector sleeps one interval before its first run, which is why the boot sweep runs first: a session shorter than a minute frees nothing and leaves the work to the next boot.

7 · Tests that define done

The headline proof

a_send_to_a_sleeping_device_is_accepted_and_lands_when_it_wakes — queue while the host is down, then bring a second host up over the same state directory and assert exactly one verified landing.

Trap in this test. Shut the host router down and drop the Host plus every Arc<RemoteNode> clone before booting the second host. router.shutdown() does not release the store lock, so a leftover clone fails the test with "another Vlerv process is already using the blob store", which reads like a queue bug and is not one.

The rest

  • a_caller_error_is_refused_outright_and_never_becomes_a_pending_delivery — every existing gate refusal, asserting today's exact wording and a spool depth of zero.
  • a_spooled_delivery_survives_the_process_that_accepted_it — the restart idiom: drop the core, rebuild over the same tempdir, assert the record reloaded intact.
  • a_claimed_store_refuses_the_send_instead_of_promising_it — hold the lock, assert the hard error and that nothing was staged.
  • an_expired_pinned_grant_is_refused_and_unpins_nothing — what stops Option<Tag> turning an expired grant into an immortal fetch capability.
  • the_grant_sweep_never_deletes_a_tag_the_spool_still_needs.
  • every_connect_failure_reports_its_own_cause_not_one_string — a table pinning cause to variant, and the Display text byte for byte.
  • an_unreadable_spool_never_lets_the_sweep_unpin_a_live_record.
  • a_full_spool_refuses_the_send_instead_of_dropping_the_oldest_file.
  • a_staged_push_replays_from_the_store_without_reading_the_source_again — stage, delete the source, assert the bytes still land. This is the whole reason bytes are captured at enqueue.
  • two_sends_of_one_file_to_one_sleeping_device_make_one_record, and the held-outside-roots case.
  • The outbox mirror set of the peer-store tests: round trip, reload, quarantine, foreign schema left untouched, id collision refused, 0600.

8 · What still does not work

LimitDetail
Delivery needs a live MCP processThe receiver dials back for the bytes, and only the store-lock holder may open the store. A file accepted at 14:00 with the terminal closed at 14:05 is delivered at the first network-touching tool call of the next session over the same state directory.
Nothing wakes a suspended iOS appIf the human never opens Vlervtifacts, no dial succeeds and the record expires at seven days. Only APNs or a background mode changes that, and both are out of scope by choice.
Two sessions, one state directoryThe second can neither send nor drain: StoreLock refuses rather than queues. It fails hard with the claimed-store message.
At least once, not exactly onceIf the host lands the bytes and the connection dies before Res::Pushed arrives, the next drain pushes again. It lands as report-2.html, so the duplicate is visible rather than silent.
Snapshot semanticsA file edited after the send is delivered as it was at send time. Deliberate, but it changes what "send this file" means, and the queued sentence must say so.
Roots differ between projectsA record whose source path is outside the current roots is held, not delivered and not dropped. Visible in server_status; nothing tells the user which session can serve it.
No cancel surfaceA queued send is withdrawn only by deleting the record file. A tool was left out because every tool is a permanent model-facing surface.
Wall-clock dependenceBackoff and expiry both use wall-clock time. A backwards jump delays retries; a forwards jump can expire a record early.

9 · Rejected alternatives

AlternativeWhy it was cut
A new vlerv/inbox/0 ALPN so the phone pulls on wakeIts whole value needs a shipped iOS build, a new foreground hook and a preference change to line up. The sender-side design already delivers whenever the phone becomes reachable for any reason, including that same dial-in.
A receiver-side delivered.json ledger for exactly-onceIt sits in the general accept path and would turn a deliberate repeat send into a silent no-op — no file, no tab, no signal.
Re-reading the source path at drain timeClaude Code edits its own reports. The delivered bytes would not be the accepted bytes, and a deleted source would fail outright.
Dropping the oldest record when the spool is fullThe oldest record is the user's file, not a log line.
String-matching the offline errorThe marker sits in the middle of a wrapped sentence. Typed errors are the only reliable signal.
APNs or UIBackgroundModesBoth need a push service that learns who is sending to whom. The promise is that nothing is uploaded to a server.

Produced from a 12-agent design run: five readers mapped the sender, host, persistence, app and test layers with file-and-line evidence; three competing designs were judged on correctness, privacy and fit; the winner was synthesized with the losing proposals' best parts grafted in and every fatal flaw the judges named fixed.

Every file-and-line reference above names the tree as it stood at commit 5f98190, the tip of main this branch was cut from — the state the design run read, before any of the code below it existed. The shipped files have moved those lines since. Read a reference as a pointer to the item it names, not to a line number in the file you have open.
