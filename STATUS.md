# Vlervtifacts — current state

## What ships

### Chrome & navigation
- **Browser-style tabs** with per-tab back/forward history (cap 50), pure reducer (`src/state/tabs.ts`, vitest-covered), drag-to-reorder, ⌘T/⌘W/⌃Tab/⌘⇧[]/⌘1-9, middle-click close, "Close Others / Close to the Right" context menu.
- **Toolbar**: sidebar toggle, back/forward/reload, editable address bar (⌘L, accepts absolute / `file://` / `vlerv://` inputs; idle it shows the **workspace-relative** path, focus swaps in the absolute path selected), bookmark star, copy path, external badge, zoom indicator, reader-mode button.
- **View modes**: ⌘B hides/shows the sidebar (persisted, `panes.sidebar_visible`); ⇧⌘F is transient reader mode — sidebar + toolbar gone, tabs + document only; Esc/⇧⌘F/⌘L/⌘B leaves it. Both forwardable from preview iframes. With the sidebar hidden the tab strip reserves the 78px traffic-light gutter.
- **Sidebar sections**: fixed header over three collapsible drawers of one shape (`SidebarSection`, per-drawer localStorage) — Bookmarks (pinned), Recent (last 8 opened, from the recents store), Files (the whole workspace tree, **folded by default**). Retrieval order: Bookmarks → Recent → ⌘P; the tree is for walking a project.
- **Start page** on empty tabs: New York serif wordmark, bookmarks + recents lists, open/pick actions.
- **Quick open (⌘P)**: fuzzy palette over `list_files_recursive` (BFS, 20k cap, ignore/hidden/symlink policy), in-house subsequence scorer, cache invalidated by watcher events.
- **Keyboard registry** (`src/keyboard/shortcuts.ts`): declarative combos, `e.code`-based exact-modifier matching; HTML preview iframes forward tab/nav/zoom/view-mode chords plus bare Escape (bound only in reader mode) via `vlerv:keydown` so those survive iframe focus (dialog/focus chords ⌘O/⌘L/⌘P are deliberately not forwardable — page content could synthesize them).
- **Per-tab zoom** (⌘+/−/0) via CSS `zoom` — host content directly, iframes via `vlerv:setZoom`.

### Live reload (the headline feature)
- Workspace watcher events + dedicated `vlerv://file-changed` events fan out through a subscription bus (`src/state/watcher-bus.tsx`) to (a) surgical Explorer folder invalidation and (b) tab auto-reload (150 ms/path debounce). Open out-of-root files are individually watched via `watch_external_paths` (parent-dir NonRecursive watches → survives atomic rename saves).
- **Scroll position survives reloads and tab switches**: iframe `vlerv:scroll`/`vlerv:restoreScroll` protocol (source-filtered), container scrollTop for md/text, `ScrollMemoryProvider` keyed `tabId::path`.
- `remove` events show a "File deleted" notice (tab kept); re-add auto-recovers.

### Beam (remote-control-design.html — v1)
- **P2P artifact transfer between Vlervcode instances** over [iroh](https://iroh.computer) (QUIC, hole-punched, encrypted relay fallback; exact-version pinned, all iroh types quarantined in `crates/vlerv-remote/`, behind the `src-tauri/src/remote.rs` facade). Lazy boot: zero sockets until the first beam action.
- **Send**: toolbar ⚡ button (or `vlerv beam <path>`, or a `vlerv://beam?path=…` link — link-initiated sends show a confirm face first). Stages the file into a content-addressed store (`ImportMode::Copy` — the ticket pins bytes at mint time), mints a `vlerv://receive?ticket=…&name=…&size=…` link. Path policy = the share module's (`canonicalize_allow_external`, conservative on empty roots).
- **Serve**: a per-request gate (`iroh-blobs` provider events) intercepts every request kind and admits only a plain full-blob GET whose hash is an active, unexpired offer — get-many / push / observe are refused explicitly. **Stop and TTL expiry revoke the in-memory offer instantly**, and the staged bytes are now really freed: the store boots with a garbage collector (`endpoint::GC_INTERVAL`, 60 s) that roots on persistent tags, so a copy nothing pins is off the disk within a minute, and every boot first sweeps the `auto-*` tags a dead process left behind (they are roots, and both registries that named them lived in memory only). Fetch counts come from the same gate. Offers live in the toolbar ⚡ indicator (name, fetches, expiry, Stop) with a Received section.
- **Receive**: deep link → confirm dialog (sanitized name — bidi/format chars stripped, size claim, sender NodeId fingerprint) → BLAKE3-verified stream (256 MiB hard cap enforced on actual bytes, 20 MiB warn) → lands under `Application Support/Vlerv/received/<date>/`, opens in a tab with a **beamed** badge. "Sender offline" is retryable from the dialog.
- **Untrusted-content isolation**: a beamed artifact is authored by the sender, not the local user, so received HTML renders in a hardened iframe — the sandbox drops `allow-same-origin` (opaque origin, no reach into the host webview / Tauri IPC) and no `file://` base-href is injected (`HtmlRenderer.isolate`, keyed on the received/ prefix). Local files render unchanged.
- **Identity**: ed25519 keypair persisted 0600 at `remote/identity.key`; corrupt key = hard error (silent regen would orphan shared tickets).
- Preferences: `preferences.beam_ttl_hours` (default 24, settable via state.json until Settings mounts).
- **Binary-size impact (measured, per design §8)**: release `vlerv-app` 12 MB → 28 MB with `iroh` + `iroh-blobs`. Larger than the design's "several-MB" guess; accepted for a local .app, revisit only if it starts to hurt.

### Scope (remote-control-design.html — v2)
- **Revocation cannot be undone by the peer** (fixed 2026-08-30). The handshake path refreshed the stored device name with an insert-or-update writer, running after the allowlist check with an await between them — so a peer revoked inside that window wrote itself back with its old scope, and the peer chose the window by stalling its `Hello` up to `HANDSHAKE_TIMEOUT`. The passive path is now `PeerStore::refresh_device`, which never inserts; `ScopeServer::accept` closes the connection when it reports the peer is gone.
- **A grant reaches disk before it reaches the allowlist** (fixed 2026-08-30). The in-memory peer list IS the allowlist `get` reads, and every writer mutated it before `save`. A refused write (a corrupt `peers.json` makes `save` refuse outright) left a device trusted for the life of the process while the caller was told it was not paired. `write` and `set_scope` now persist a candidate list and commit only on success. `remove` deliberately keeps the old order: revocation taking effect even when the write fails is the safe direction.
- **Pairing**: `vlerv://pair?ticket=…` deep link (or QR-scannable equivalent) mints a one-time pairing token; both sides confirm a **six-word fingerprint** derived from both NodeIds before the peer is persisted. Peers live in `remote/peers.json` (NodeId, device name, granted scope, paired-at, last-seen); revocation is deleting the entry.
- **Getting the invite to the other device**: Settings offers Copy link *and* Share. Share opens the native sheet — AirDrop, Messages, Mail — with the link as a URL, so the recipient taps it and the `vlerv://` handler opens it. macOS routes through the `share_link` command (NSSharingServicePicker; `share.rs` admits a link only if `deeplink::parse` accepts it as `Pair`/`Receive`, so the sheet cannot carry a link the recipient's app would refuse, nor a path-carrying verb). iOS has no UIKit bindings in this build and uses the WKWebView Web Share API (`src/utils/share-link.ts`). **One `share()` call per click**: it requires transient user activation and consumes it, so a retry after a rejection always fails with `NotAllowedError` — `canShare()` picks URL-vs-text *before* the call instead. A failed share flips the button to "Share failed" rather than doing nothing. Where neither route exists the button does not render.
- **A failed dial is visible** (fixed 2026-08-30). `completePairing` stored the failure in `pairingError`, but the link-arrival face rendered neither it nor `pairingBusy` — tapping Continue on a dial that could not reach the peer changed nothing on screen. `PairLinkFace` now shows "Connecting…" on a disabled button while the dial runs, and renders the error above the actions, the way the fingerprint face already did.
- **Fingerprint dialog stacking**: `RemotePairDialog` sits above the Settings surface (`.beam-backdrop` z-index 150 vs `.settings-backdrop` 100). A pair link normally arrives while Settings is open, and six words that a dialog covers cannot be compared.
- **Scope server/client** under ALPN `vlerv/scope/0`, multiplexed on the same iroh endpoint as Beam's blob ALPN. Scopes: `view-open`, `browse`, `control`.
- **Remote sidebar drawers**: a paired, online peer appears as a fourth drawer beside Bookmarks/Recent/Files — live tab list, lazy workspace tree under `browse`.
- **Live-follow**: a drawer toggle mirrors the host's active tab as it switches.
- **`control` scope / `OpenOnHost`**: a `control`-scoped peer can push-open an artifact on the host — the literal remote control.
- Known gap: `remote_set_scope` narrowing an existing peer's scope does not revoke grants already minted under the wider scope — those stay valid for up to 1 h.

### MCP server (crates/vlerv-mcp)
- Stdio MCP server named `vlerv-mcp` (rmcp 3.1.4) that exposes Remote Control to external agents: `beam_artifact`, `list_devices`, `send_to_device`, `pair_device`, `pair_status`, `confirm_pairing`, `forget_device`, `stop_beam`, `server_status`.
- Configured via env: `VLERV_MCP_ROOTS`, `VLERV_MCP_STATE_DIR`, `VLERV_STATE_DIR`.
- Built on the Tauri-free `crates/vlerv-remote` core, so the MCP binary carries no Tauri dependency.
- Documented in `README-MCP.md`.
- Registered with Claude Code via `claude mcp add vlerv --scope user --env VLERV_MCP_ROOTS=<dir> -- <path>/vlerv-mcp`. `VLERV_MCP_ROOTS` is a hard send boundary, not a hint. (Node id, roots and pairing state are per-machine and deliberately not recorded here.)
- **Session cache prunes itself**: a `ClientSession` that closes evicts its own entry through the `on_closed` callback, so a long-lived server no longer holds one dead connection per probed device. Guarded on `is_closed`, so a re-dial that already replaced the entry survives. Covered by the two-endpoint integration test (revoke on the host → the cache drains).
- **The pushed-artifact list is bounded** at `MAX_RECEIVED` = 100, oldest dropped; `ServerStatus::received_total` reports the true count and `server_status` says "(listing the last N)" when the two differ.
- **`confirm_pairing` applies the scope the human named**, in both directions. A named scope replaces an already-trusted device's grant — re-pairing a `control` peer at `view-open` now actually narrows it, where before the narrowing was dropped with no error. Omitting the scope names no grant, so an existing peer keeps what it has and a new one gets `view-open`. The rule lives in one place, `PeerStore::confirm`; `remote_pair_confirm` in the app uses it too.
- **A second server on one state dir is refused, not hung** (fixed 2026-09-01). Every Claude Code session spawns its own `vlerv-mcp`, and all of them pointed at one `remote/blobs` — a redb database only one process may own. The second process did not fail: it HUNG. redb is not the culprit — it reports `DatabaseAlreadyOpen` at once; unwinding THAT error deadlocks inside `iroh_blobs::store::fs::RtWrapper::drop`, which drops a tokio runtime from inside `block_in_place` (confirmed by `sample`: that stack held 100% of the run). A `timeout` around the load does return, because the wedged drop runs on the store's own private runtime rather than in the caller's poll — but it rescues nothing: each attempt leaks a wedged worker thread and a runtime that never shuts down, and still yields no store. Two consequences, both silent — `beam_artifact` never returned, and because `node()` holds its mutex across the whole boot, `booted()` then blocked too, so even `server_status` stopped answering for the life of the process. Observed in the wild: an orphaned headless session had held the store for 30 hours, and Beam was dead in every session started after it. `endpoint::boot` now takes an exclusive `File::try_lock` on `Dirs::blobs_lock` (`remote/blobs.lock`) as its FIRST act, before it reads the identity key, binds a socket or opens the store, so a refused boot does none of that work. A filesystem with no locks (NFS/SMB) is told apart from contention and gets its own remedy. The remedy in the message stays generic ("its own state directory"): `boot` is shared, and the two consumers name that directory with different variables. `McpCore::node` moved from `Mutex<Option<_>>` to `OnceCell`, so `booted()` is a plain synchronous read — a mutex held across the boot also blocks the read side, and the `try_lock` that would dodge it answers "not booted" for a server that IS serving, which would make `stop_beam` report a live link as already dead. `get_or_try_init` does not cache a failure, so a refusal stays retryable once the other process exits. That non-blocking read also opened a race that review caught: `server_status` falls back to `node_id()`, which could then run WHILE `boot` was inside `load_or_create_identity`, and `create_private` writes its 32 bytes in a second step after `create_new` — so a reader saw an empty file and was told the user's key was corrupt. `load_or_create_identity` is now concurrency-safe: it re-reads a short file, and the loser of a `create_new` race reads the winner's key instead of failing. **An empty answer is never the answer to a refusal**: `stop_beam` errors rather than reporting "nothing to revoke", `list_devices { probe: true }` errors rather than calling every device offline, and `ServerStatus::boot_error` carries the reason beside `booted: false`. Measured: second process now answers `server_status` in 0.0 s and refuses `beam_artifact` in 0.0 s, and mints normally 3.2 s after the first exits.
- **A send to a device that is not there is queued, not lost** (2026-09-02). `send_to_device` failed with "the session is closed" whenever the phone had suspended, and no retry helped: `is_closed()` is a cached `AtomicBool`, not a probe, so the cached session was handed out and the failure arrived from `request` rather than from a dial. Failures are now classified where the cause is known (`ConnectError::Unreachable` vs `Refused`; `PushFailure::Local` / `Transport` / `Denied`), a transport failure re-dials once, and the two queue doors are `Attempt::Asleep` — the dial found nobody — and `Attempt::SessionDied`, a session that died again under the request on a fresh dial. Every other failure leaves through `Err` and never reaches the spool. The bytes are copied into the blob store at the moment of the send — a snapshot, so later edits to the file do not change what arrives — and pinned under a persistent `outbox/<id>` tag, with one 0600 record per send in `remote/outbox/`. The drain is owned by the holder of the blob-store claim, which is the only process that may open the store: one pass at boot, one when the device dials in (`HostSignal::PeerConnected`), and a 60 s tick with a per-peer backoff ladder (60 s, 2 min, 5 min, 10 min). `Delivery` is a tagged enum, so no renderer can print a queued send as a delivered one, and `server_status` reports the spool, what it weighs, what it retains, whether a pass is running and why it can move nothing. Records expire at 7 days; the queue refuses at 64 records or 1 GiB rather than dropping the oldest file; a device whose last handshake reported less than `control` is refused instead of queued for, because the copy would be private, full and useless. A record whose source has left `VLERV_MCP_ROOTS` is held and says so rather than being dropped or sent.
- **A device that unpaired this server says so, and there is a way out** (2026-09-04). `ScopeServer::accept` refuses a dial from an unlisted node by closing the QUIC connection with the reason `not a paired peer`, before `accept_bi`, so no application frame carries it. The sender never read `connection.close_reason()`, printed `stream ended: connection lost`, and told the user to check a device that was awake and refusing on purpose. `ClientSession::connect` now recovers that reason at each post-dial failure (the handshake timeout still does not: a peer that says nothing has closed nothing, and that one really is asleep), bounded and stripped like any other text from another machine. `dial_failed` picks its advice from the variant, `list_devices` reports a probed device as `refused` rather than `offline`, and `ScopeState::drop_sessions_for` now cuts the peer's live connection instead of leaving it up until that peer's next request. `forget_device` is the exit that did not exist: it removes the pairing, drops the cached session, deletes every queued record for that device and unpins the staged copies, in one call — the pairing first, so a cleanup that fails cannot destroy sends for a device that is still paired.
- **A refused record no longer holds the queue** (2026-09-04). A drain pass spends `MAX_PER_PASS` on pushes, and a record the device refuses stays at the head in the same id order — eight of them owned the whole budget until their expiry. A refused record now rests on the same `RETRY_LADDER` its peer uses, derived from `attempts` and `last_attempt_at`, and a record that is not due is skipped with no budget. `record_denial` always counts, unlike `record_attempt`, because a refusal cost a session round trip where a hold cost a string compare. A `Wake::Peer` pass ignores the rest, so a phone that dials in still drains at once.
- **A delivery this server gave up on is reported** (2026-09-04). `server_status` carries `abandoned`: the sends that expired or were dropped, each with the file, device, size and reason. In memory only — the record is gone by then — so it reports what this process ended, and says so.
- Known gap: no per-peer push quota on `send_to_device` / `beam_artifact`.
- Known gap: `list_devices { probe: true }` dials each device, and an offline peer costs the full `PROBE_TIMEOUT`. The probes run concurrently (`join_all`), so the call bounds at about one timeout (12 s) however many devices are paired, not one per device.

- **Live E2E succeeded (2026-08-29)**: the MCP server paired with the simulator app via a `vlerv://pair` deep link and pushed an artifact that opened on the phone.
- **Phone-adapted layout** (`PhoneShell.tsx`): on iOS the desktop panes never mount. One column — a 40px title band (active artifact's basename + a live-reload pulse dot in the accent), the artifact full-bleed, and a bottom bar at the thumb (Library, back/forward, tab count). Same design tokens as the desktop — the phone changes the architecture, not the language.
- Theme: Tauri's `window.theme()` reports "light" on iOS regardless of the trait collection, so `useTheme` skips the Tauri probe on iOS (UA check — the `platform-ios` body class arrives async and would race it) and trusts `prefers-color-scheme`, which WKWebView tracks correctly.
- **The phone listens on a default install** (2026-09-02). `preferences.remote_listen` defaults to false and `listen_at_launch` returned before it spawned anything, so a phone that had been paired still bound no socket and no send could ever reach it — the queue would have accepted files nothing delivered. The rule is still "peers AND the preference" on both platforms, but the phone ADOPTS the preference: the first launch where its peer store is not empty turns `remote_listen` on once and records that it did, so the stored value matches what the app does. The Settings toggle stays visible there, and a user who turns it back off is obeyed — the migration is one-way. A fresh install with zero peers still binds nothing. Returning to the foreground (`WindowEvent::Resumed`, which is `applicationWillEnterForeground` — not `RunEvent::Resumed`, which is a poll) drops every cached session, emits a `resumed` remote event and re-dials each paired peer, so a suspension whose `is_closed()` still reads false cannot leave a dead session in the cache. A delivery run opens only its first artifact in a tab and refreshes the Received list for the rest.
- Known gap: device name shows the Mac hostname on the simulator, not a real iOS device name.

## Open items

- **Beam follow-ups** (remote-control-design.html M6): single-fetch mode, lock-to-peer beams, Open-in-Slack for the beam *link* and wiring `ShareLinkButton` into `BeamDialog` (the `share_link` command ships and the pairing invite already uses it; BeamDialog is still Copy-link only), Settings UI for `beam_ttl_hours`, macOS application-firewall prompt doc for unnotarized inbound. `endpoint.online()` waits up to 10 s before minting when relays are unreachable (e.g. behind some VPNs) — the ticket still carries direct addrs.
- **Scope follow-ups**: `remote_set_scope` narrowing an existing peer's scope does not revoke grants already minted under the wider scope (valid up to 1 h after narrowing); no per-peer push quota on MCP/Scope pushes.
- **Queue follow-ups**: delivery still needs a live `vlerv-mcp` against the same state directory, so a send accepted at 14:00 with the terminal closed at 14:05 goes out at the first network-touching tool call of a later session, not before. Delivery is at-least-once: if the bytes land and the connection dies before `Res::Pushed` gets back, the next pass sends the same file again and the Beam collision rule lands it as `report-2.html` — visible rather than silent. A record whose source has left the current roots is held, and nothing tells the user which session could serve it. There is no `cancel_queued` tool for ONE record: withdrawing a single accepted send still means deleting its record file, though `forget_device` now withdraws every send for one device and unpins the copies with them. Re-pairing a device revoked while the process was down can resurrect its records, because the drop happens in a drain pass.
- **Dropping a booted node no longer closes its blob store** — the collector task holds a store handle for the store's whole life, so the actor never sees its last sender go and redb stays open while the lock file says the store is free. A process that hands its state directory to another opener WITHIN its own lifetime must call `RemoteNode::shutdown`; the MCP drain supervisor does exactly that when its core is dropped.
