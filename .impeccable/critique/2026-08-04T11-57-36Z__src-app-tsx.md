## Design Specificity Verdict

**The color and type system is authored for this product. The composition and interaction model is not, and one file imports a competitor's visual language wholesale.**

Genuinely product-specific: the warm ink/paper token system; the 2px-marker grammar applied across four unrelated components; the address bar as a path/scheme field; the `external` custody badge; the deleted-file notice; the iframe chord-forwarding allowlist that keeps ⌘T/⌘W alive inside untrusted content while refusing ⌘O/⌘L/⌘P.

Category-interchangeable: `src/components/FileIcon.tsx` in full — roughly 110 hardcoded hex values following the VS Code / Seti icon-theme convention, including `#3178c6`, `#42a5f5`, `#7bafd4`, `#9aa0a6`, `#a8b9cc` — the exact cool blue-grey DESIGN.md names as an anti-reference. Tab strip geometry, toolbar layout, quick open, context menu and start page are all correct and none are invented here.

**The sharpest gap:** the product is about artifacts generated continuously by agents across ~100 repos. Nothing in the interface represents an artifact, a repo, a generation event, or what is new. `watcher-bus` knows exactly which paths just changed and spends that entirely on cache invalidation. Recents rank by open-order, not write-time. Quick open with an empty query returns `files.slice(0, 50)` in BFS walk order. The app is addressed to files; the product is about artifacts.

**Deterministic scan:** `detect.mjs --json src index.html` exited 2 with **61 findings** — `design-system-color` 51, `design-system-font-size` 5, `design-system-radius` 4, `side-tab` 1.

Verified: all 51 color findings are TRUE positives, every one in `FileIcon.tsx` lines 23–147. Two radius findings are true (`3px` at styles.css:685 and :852, outside the 4/6/10 scale) and two are FALSE (`5px` at :1008 and :1047 are documented in DESIGN.md). Three font-size findings are FALSE (10px bookmarks, 14px explorer row, 10px quick-open footer are all documented), one is true (14px quick-open input), one is unresolved (10px kbd chip). `side-tab` at styles.css:505 is a literal pattern match on a Markdown blockquote using `var(--accent)` — a false positive in context.

The detector and the design review converged independently on `FileIcon.tsx`. That is the report's strongest signal.

## Overall Impression

The hard parts are done well and the easy parts are unfinished. The keyboard architecture, the security posture, and the token system are the work of someone who thought carefully. Then the file icons import another product's palette onto every surface, the app forgets every open tab on quit, and the retrieval surfaces dim and truncate the exact text that decides which file you open.

The single biggest opportunity: the app already computes everything needed to answer "what changed while I was away" and shows none of it.

## What's Working

1. **The deleted-file notice** (`TabView.tsx:43-61`). Centered, iconed, titled, states the recovery behavior in plain words, offers one sensible action. It answers what happened, is it lost, and what do I do — in that order, without jargon. It is the only state in the app authored as an experience.
2. **The 2px-marker language** (`styles.css:236-244, 246, 663-665, 723-725`). Active tab, selected row, tab drop target, bookmark drop target: four unrelated components, one grammar, one hue. It works because it is a rule, not a style — a new component has an obvious correct answer for "how do I say active".
3. **The keyboard architecture** (`keyboard/shortcuts.ts` + `App.tsx:45-51` + `render/html.tsx:100-121`). `e.code` matching with exact-modifier comparison means ⌘[ never swallows ⌘⇧[, and the forwarding allowlist keeps navigation alive when focus sits inside untrusted artifact content while refusing the chords page content could weaponize. The hardest interaction problem in the app, solved cleanly.

## Priority Issues

### [P0] The file-icon palette overwrites the design system on every surface at once

**Why it matters:** `FileIcon.tsx:21-128` hardcodes ~110 saturated hex values, several of them the cool blue-grey DESIGN.md names as an anti-reference. These glyphs render in Explorer rows, tab icons, quick-open results and start-page lists, so the Single Lamp Rule is violated on every pixel-bearing surface simultaneously. The ember accent — the system's only carrier of state — competes with dozens of louder hues that carry no state at all. The detector independently flagged all 51 lines.

**Fix:** Delete the `color` field from `EXT_MAP` and `BASENAME_MAP`. Render every glyph with `currentColor` so it inherits `--fg-muted` at rest, `--fg` on hover and `--label-active-fg` on selection. Keep the shape mapping (`FileText`/`FileCode`/`FileJson`/`FileImage`) — that is the part carrying information. If a tonal channel is wanted, allow exactly two: `--fg` for `.html` and `.md` (the product's subject) and `--fg-dim` for everything else.

**Suggested command:** `/impeccable colorize`

### [P1] The reading session is not persisted

**Why it matters:** `initialTabsState()` (`state/tabs.ts:89-92`) always returns one empty tab, `TabsProvider.tsx` writes no tab state, and `App.tsx:120-133` restores only `panes.sidebar_px`. Verified: there is no persistence call anywhere in the provider. Every relaunch discards the open set, per-tab history and per-tab zoom. Window geometry survives quit; the reading session does not. An app whose north star is custody drops everything it was holding at the door.

**Fix:** Debounce-persist `{tabs: [{history, historyIndex, zoom}], activeTabId}` through the existing `ipc.setStateField` surface, rehydrate in `initialTabsState`, and drop entries whose paths no longer resolve at load. Add ⌘⇧T backed by a closed-tab stack in the reducer at the same time. Scroll memory is already keyed `tabId::path`, so restored tabs can land where they were left.

**Suggested command:** `/impeccable harden`

### [P1] The retrieval surfaces truncate and dim away the text that does the disambiguating

**Why it matters:** `.start-row-dir` and `.quick-open-dir` (`styles.css:892-901, 966-975`) are right-aligned with `text-overflow: ellipsis`, which cuts the tail. `StartPage.tsx:42` feeds them `dirname(path)` — a full absolute path. In `~/workspace/`, `report.html` from `evm-wal` and `report.html` from `clud` render identically: same visible prefix, repo name cut off. Contrast measured: `--fg-dim` on `--bg-elevated` is **2.77:1** at 11px and on `--bg-sidebar` **3.17:1**. In the light theme it is **2.62:1**. The least legible text in the app is the text that decides which file you open.

**Fix:** Truncate from the head, not the tail. Show the path relative to the workspace root on the start page, as quick open already does. Add a `--fg-path` token at 4.5:1 or better on both `--bg-elevated` and `--bg-sidebar`, in both themes.

**Suggested command:** `/impeccable clarify`

### [P1] Keyboard reachability has holes, in a keyboard-first product

**Why it matters:** PRODUCT.md states this product prefers keyboard depth over discoverability aids. Four concrete holes, all verified in source:

- **The tab strip is unreachable by keyboard.** `TabStrip.tsx:80-82` renders `role="tab"` divs with no `tabIndex` and no `aria-controls`, and the content region is not a `tabpanel`. Tabs are switchable only by chord, never focusable.
- **Focusable controls are invisible.** `.tab-close` (`styles.css:282`) and `.bookmark-remove` (`styles.css:690`) sit at `opacity: 0`, revealed only on `:hover`. Both are real buttons in the tab order, and the global `:focus-visible` ring cannot show through `opacity: 0`.
- **Tree focus can be lost entirely.** The container is `tabIndex={focusedPath ? -1 : 0}` (`Explorer.tsx:371`). Collapse an ancestor of the focused row and that row unmounts while `focusedPath` stays truthy, so nothing in the tree holds `0` and the tree drops out of the tab order until a mouse click restores it.
- **Quick open is not a real dialog.** `role="dialog"` with no `aria-modal` (`QuickOpen.tsx:115`), no focus trap, and `onMouseEnter` reassigns `selectedIndex` (`QuickOpen.tsx:140`) — trackpad drift silently retargets a keyboard selection mid-type.

Screen-reader semantics are weaker still — flat `treeitem` rows with no `role="group"`, mouse-only bookmark rows, an `<h4 role="button">` that discards heading semantics — but that is P2 for this product: no VoiceOver user exists today, and PRODUCT.md records the current ARIA work as a floor to preserve rather than a target to raise.

**Fix:** Add roving `tabIndex` and arrow-key handling to the tab strip with a matching `tabpanel`. Reveal `.tab-close` and `.bookmark-remove` on `:focus-visible`, not only `:hover`. Fall back to `tabIndex=0` on the tree container when `focusedPath` is not mounted. Trap focus in quick open and ignore `mouseenter` until the pointer actually moves.

**Suggested command:** `/impeccable audit`

### [P2] The chrome stops short of its own doctrine, and one token makes live reload flash

**Why it matters:** DESIGN.md now commits to solid and substantial components and a layered and lifted elevation model. The dark build is the opposite by measurement, not by opinion: `--bg-sidebar #151311` → `--bg #1c1a17` → `--bg-row-hover #26221d` are 1–3% luminance steps, and `--border #2b2721` on `--bg-sidebar` is **1.25:1** — a plane change at the perceptual floor. The only structural cue that survives is the 2px ember bar. Three further defects compound it:

- **A white flash on every artifact load.** `--iframe-bg` is `#ffffff` in *both* themes (`styles.css:68, 106`). In dark mode every HTML load and every live reload flashes white before `srcdoc` paints. On a save-driven workflow that repeats dozens of times an hour, in the app's headline feature.
- **A broken horizontal rule.** The sidebar header's bottom border lands at ~68px while the toolbar's lands at 78px, so the second line across the window is off by ~10px. The 38px Aligned Band Rule holds; the band below it does not.
- **No grouping in the toolbar.** Nine controls, all 28×28, all `--fg-muted`, all transparent, at uniform 4px gaps. Navigation and file actions are visually indistinguishable. Two `RotateCw` buttons 40px apart do different things.

Failure states are unfinished in the same way: `preview-error` (`TabView.tsx:64-73`) is three unstyled paragraphs with a raw Rust enum as its heading and no action, thirty lines below the deleted-file state that does everything right. `.app-notice` is `flex: 0 0 auto` in the column, so it pushes the artifact down and back up six seconds later with no dismiss.

**Fix:** Set `--iframe-bg: var(--bg)` in the dark block first — one line, removes the worst repeated irritation. Widen the dark tonal ramp (chrome toward `#100e0c`, `--bg-elevated` up to ~`#292520`) and strengthen `--border` to roughly `#3a342c`. Add separator hairlines after the nav trio and before the file-action group, and give the sidebar header the toolbar's 40px height so the second rule runs unbroken. Rebuild `preview-error` on the `.deleted-notice` structure with a human title, Retry, and Reveal in Finder. Take `.app-notice` out of the flex column and give it a dismiss control.

**Suggested command:** `/impeccable layout`

## Questions to Consider

1. The watcher already knows every changed path and the app discards it. What if the tab strip marked reloaded background tabs with the ember dot, and ⌘P's empty query returned changed-since-last-focus first? That is a feature built entirely from data already in memory.
2. If the tree is read-only and the workspace holds ~100 repos, why is the primary navigation surface a filesystem tree at all? What would the sidebar be if its top level were recent artifact activity, with the literal tree demoted to a secondary mode?
3. Quick open indexes 20,000 files and matches filenames. Every artifact has a title inside it. What does retrieval feel like if the palette matched `<title>` and `# heading` instead of paths — and would the path column still need to exist?
4. `Settings.tsx` is unmounted because placement was deferred. Is the answer a panel at all, or are `drag_out_mode` and `slack_target` inline decisions at the point of use, leaving no settings screen to place?
5. DESIGN.md commits to "solid and substantial" while the build is deliberately weightless so the artifact can be the hero. A defensible answer is to make the custody surfaces substantial — sidebar, quick open, tabs — and keep the reading surface weightless. The system has not made that decision in either direction.
6. If this is a reading room, why does closing it forget what was on the desk?
